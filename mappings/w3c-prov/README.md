# AuditSpec ↔ W3C PROV mapping

W3C PROV provides a formal model for provenance. AuditSpec provides concrete application-audit semantics. A mapping between them lets AuditSpec events participate in broader provenance graphs without replacing the AuditSpec event model.

## Conceptual mapping

| AuditSpec | W3C PROV concept |
| --- | --- |
| AuditSpec event/action occurrence | `prov:Activity` |
| `actor` | `prov:Agent` associated with the Activity |
| delegation principal | `prov:Agent` |
| `delegation.relationship: on_behalf_of` | `prov:actedOnBehalfOf` |
| targets/subjects | typically `prov:Entity` when they represent resources/data |
| `producer` service/runtime | may be represented as `prov:SoftwareAgent` |
| `occurred_at` | Activity timing/provenance time context |
| derived evidence | provenance relationships to source entities/activities |

## Delegation example

AuditSpec:

```json
{
  "actor": { "type": "agent", "id": "agent_child" },
  "delegation": [
    {
      "relationship": "delegated_by",
      "principal": { "type": "agent", "id": "agent_parent" }
    },
    {
      "relationship": "on_behalf_of",
      "principal": { "type": "user", "id": "usr_42" }
    }
  ]
}
```

Conceptually produces a provenance responsibility chain:

```text
agent_child  acted on behalf of/delegated from  agent_parent
agent_parent acted on behalf of                  usr_42
```

The exact PROV serialization is mapping-specific and may use PROV-O/JSON-LD in a future executable adapter.

## Activity vs event record

An AuditSpec JSON document is a record asserting facts about an action occurrence. In a PROV graph, the audited action is best modeled as the Activity, while the AuditSpec document itself may additionally be modeled as an Entity generated by the audit producer.

This distinction becomes useful for integrity/provenance systems because it separates:

- the business activity being asserted
- the evidence record that asserts it
- the software agent that produced the record

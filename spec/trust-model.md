# Evidence trust model

Audit data has different evidentiary strength depending on where each observation was produced.

AuditSpec therefore models `evidence` as a collection rather than a single producer assertion.

Trust levels:

- `authoritative` - generated by the system that enforced or executed the specific asserted action.
- `attributed` - generated by a trusted intermediary with attributable identity.
- `self_reported` - generated by the actor or actor-controlled runtime.
- `derived` - inferred from other evidence.

Example:

```json
{
  "evidence": [
    {
      "kind": "execution",
      "producer": { "name": "erp-service" },
      "trust": "authoritative"
    },
    {
      "kind": "agent_report",
      "producer": { "name": "agent-runtime" },
      "trust": "self_reported"
    }
  ]
}
```

A local coding-agent plugin reporting its own tool call is useful evidence, but it is weaker than an authoritative server that actually executed and authorized the tool call.

Multiple independent evidence sources may corroborate an assertion. Corroboration increases confidence but does not magically turn a weaker producer into an authoritative one.

OpenTelemetry, OS telemetry, or eBPF observations may be strong runtime evidence while still being unable to establish application-level business semantics by themselves.
